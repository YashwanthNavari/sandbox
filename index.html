Security Gap

Strong authentication alone does not guarantee that the session remains secure after login.

  • Unauthorized session access — another person may access an already unlocked system.
  • Suspicious process activity — potentially harmful or unexpected processes may execute after login.
  • Repeated authentication attacks — failed attempts and abnormal login patterns may indicate an attack.
  • Limited unified visibility — security events handled by separate mechanisms.
Key Gap: Security must continue after authentication—not stop at successful login.
Our Project Direction

Understanding Today's Desktop Security Threats

Traditional desktop authentication protects the login, but not the system after access is granted.

Credential Theft
Most security breaches stem from stolen passwords or compromised user credentials.
Automated Brute Force
High-frequency password cracking scripts hammering offline hashes and weak login PINs.
Physical Desktop Hijacking
Unauthorized local execution and data tampering following unattended terminal sessions.
Network Credential Sniffing
Remote cloud endpoint syncs exposing unencrypted authentication traffic to local listeners.
Existing Systems Limitations
  • Cloud Dependent & Network Exposed
  • Single Password Authentication Factor
  • Minimal Post-Login Security Monitoring
Proposed System Protection
  • 100% Local-First Privacy Architecture
  • Continuous Real-Time Watchdog Observer
  • Encrypted Local Audit Event Logging

Literature References

Primary research papers forming the foundation of the proposed Secure Desktop Authentication and System Protection Application.

Continuous Authentication
A Review of Continuous Authentication Using Behavioral Biometrics
I. Stylios, O. Thanou, I. Androulidakis, E. Zaitseva • SEEDA-CECNSM 2016 (ACM) • DOI: 10.1145/2984393.2984403
Contribution to Project: Establishes that traditional one-time authentication is insufficient and introduces continuous authentication through behavioral biometrics. This research provides the foundational basis for our system's real-time monitoring of authenticated user sessions. By continuously evaluating user behavior patterns, it enables our architecture to seamlessly detect anomalies without interrupting the user experience.
View the paper ➔
Zero Trust Architecture
Zero Trust Architecture: A Systematic Literature Review
M. L. Gambo, A. Almulhem • Systematic Literature Review (PRISMA), 2025 • arXiv: 2503.12362
Contribution to Project: Explains core Zero Trust principles such as continuous verification, least privilege, and dynamic trust evaluation. This review forms the architectural blueprint for our proposed desktop security application. It justifies our integration of encrypted local audit trails, strict resource isolation, and continuous state re-verification to ensure no internal activity is implicitly trusted.
View on arXiv (2503.12362) ➔
THEORETICAL FOUNDATION: These research papers provide the theoretical foundation for continuous authentication, Zero Trust security, and adaptive desktop protection, which directly motivate the proposed system.
